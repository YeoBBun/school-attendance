# 출결·서류 관리 웹앱 설계

담임교사가 학급 학생의 출결 상황과 증빙서류 수합을 한 곳에서 관리하는 웹앱. 기준 학교: 원묵중학교.

## 사용자·운영 방식

- 사용자: 담임교사 1인 (학생·학부모는 사용하지 않음)
- 서류는 종이로 받고, 앱에서는 **받았는지 여부만 체크**한다 (파일 업로드 없음).
- 데이터는 교사 브라우저의 IndexedDB 에만 저장한다. 외부 서버로 전송하지 않는다.
  - 다른 기기로 옮기거나 브라우저 데이터를 지울 때를 대비해 **백업 파일(JSON) 저장·불러오기**를 제공한다.
  - 마지막 백업 후 7일이 지나면 상단에 알림을 띄운다.

## 출결 분류

- 상황: 결석 · 지각 · 조퇴 · 결과
- 종류: 출석인정 · 질병 · 미인정 · 기타
- 출석인정 세부 사유: 법정감염병 · 체험학습 · 경조사 · 생리 · 공문
- 결석은 기간(시작~종료)으로 입력하고, 결석일수는 **수업일**(토·일요일, 공휴일, 재량휴업일 제외)만 센다.
- 결과는 해당 교시를 기록한다.
- 기타 결석: 학교장이 인정하는 부모·가족 봉양, 가사 조력, 간병 등 (드묾)

## 상세 사유

모든 출결 입력에 상세 사유(예: 감기, 생리통)를 반드시 입력한다. 체험학습은 예외(사유가 곧 체험학습). 첫 화면 출결 현황의 괄호 안에 표시된다.

## 필요서류 자동 생성

| 기록 | 결석계 | 증빙 |
|---|---|---|
| 출석인정 (결석·지각·조퇴·결과) | 필수 (체험학습 제외) | 사유별 (아래) |
| 질병 결석 | 필수 | 진료확인서 등 (필수) |
| 질병 지각·조퇴·결과 | 없음 | 진료확인서 등 (선택, 담임 재량) |
| 미인정 · 기타 | 없음 | 없음 |

출석인정 사유별 증빙:

| 사유 | 증빙 |
|---|---|
| 법정감염병 (독감, 코로나19, 백일해 등) | 의사 소견서 |
| 체험학습 | 체험학습 신청서, 체험학습 보고서(사진 등 첨부) |
| 경조사 (결혼, 입양, 사망 등) | 청첩장·사망진단서 등 |
| 생리 | 없음 |
| 공문 (대회 참가 등) | 공문 |

- 각 서류의 필수/선택은 기록마다 바꿀 수 있고, 서류를 직접 추가할 수도 있다.
- 출결 종류를 바꾸면 서류 목록을 다시 만들되, 이미 받은 서류 상태는 유지한다.

## 규칙 검사 (경고만, 자동 변경 없음)

규칙에 어긋나도 앱은 기록을 바꾸지 않고 경고만 띄운다. 판단은 담임이 한다.

- **생리**: 지각·조퇴·결과·결석을 통틀어 **달력 월 기준 월 1회**. 같은 달 두 번째 기록부터 경고. 여러 날 결석도 경고.
- **법정감염병**: 의사 소견서에 적힌 기간 밖의 날짜가 있으면 경고. 소견서 기간 미입력도 경고.
- **체험학습**
  - 신청서: 실시 2일 전까지 (기본 **수업일 기준** — 결재는 수업일에만 가능하므로)
  - 보고서: 실시 후 7일 이내 (기본 **달력 날짜 기준**)
  - 위 두 기준은 설정에서 수업일/달력 중 선택 가능
  - 국외: 1회 연속 10일 이내 (수업일 기준)
  - 국내+국외 연간(학년도) 총 20일
  - 반일(0.5일) 단위 가능: 하루짜리 오전은 인정지각, 오후는 인정조퇴. 여러 날이면 첫날 오후부터(첫날 인정조퇴)·마지막 날 오전까지(마지막 날 인정지각) → 1.5일, 2.5일 등. 기록 하나로 묶고 서류도 한 벌.
  - 보호자 미동반 교외체험학습 불가
  - **사후 신청 불가**: 기한 지나 받은 신청서, 신청서 없이 실시한 경우 "미인정 처리 대상" 경고
  - 결재 여부는 앱에서 관리하지 않음
- **공통**: 결석 기록이 같은 학생의 다른 기록과 날짜가 겹치면 경고. 결석 기간에 수업일이 없으면 경고.

## 화면

1. **오늘 (첫 화면, 모바일 우선)**: 날짜(◀▶ 이동)와 아래 네 가지만 보인다.
   - **오늘 출결 현황**: "1. 김철수 : 질병결석 (감기)" 목록, 복사 버튼. 줄을 누르면 그 학생 기록. 경고가 있으면 ⚠ 표시.
   - **출결 입력**: 누르면 학생 명단 → 학생 선택 → 상황·종류(·사유)·상세 사유 → 저장 후 명단으로 돌아와 이어서 입력.
   - **체험학습 신청 접수**: 학생·기간·국내/국외·보호자 동반. 하루면 종일/오전/오후, 여러 날이면 첫날 종일/오후부터·마지막 날 종일/오전까지 (1.5일, 2.5일 등). 남은 연간 일수와 경고를 저장 전에 표시. 신청서는 접수일로 받음 처리.
   - **받아야 할 서류**: 기한 지난 것 먼저, "받음" 버튼. 체험학습 보고서는 접수 때부터 표시.
   - 모바일에서는 탭이 화면 아래에 있고 입력창은 전체 화면으로 열린다.
2. **현황판**: 학생별로 상황×종류 표(결석은 일수, 나머지는 횟수), 총결석일수, 출석인정 결석일수, 체험학습 사용 일수(학년도 누적/20), 누락서류 수, 경고 수. 학년도·월 단위로 보기, CSV(엑셀) 내보내기. 학생을 누르면 해당 학생의 기록 목록.
3. **출결 기록**: 학생·월·누락·경고로 거르는 기록 목록. 서류 칩을 눌러 바로 받음 처리. 새 기록은 여러 학생에게 한 번에 입력 가능.
4. **달력**: 월 달력에 날짜별 출결 표시. 날짜를 눌러 출결 추가, 재량휴업일·공휴일 지정/해제 (갑자기 생기는 재량휴업일 대응).
5. **설정**: 학급명, 학생 명단(엑셀 붙여넣기), 휴일 관리, 체험학습 규정 수치, 백업.

## 집계 기준

- 학년도: 3월 1일 ~ 다음 해 2월 말
- 총결석일수 = 질병 + 미인정 + 기타 결석일수 (출석인정 제외)
- 출석인정 결석일수는 따로 표시
- 출결 통계는 **오늘까지만** 센다 (미리 접수한 체험학습 등 예정 기록 제외)
- 체험학습 일수는 사용(오늘까지)과 예정(내일부터)을 나눠 "5+3/20"처럼 표시
- 지각·조퇴·결과의 결석 환산은 하지 않음

## 기술 구성

- Vite + React + TypeScript, 서버 없는 정적 웹앱
- 저장: IndexedDB (`attendance-app` DB), `navigator.storage.persist()` 요청
- 도메인 로직(`src/domain`)은 UI와 분리하고 Vitest 로 테스트

```
src/
  domain/
    types.ts      데이터 모델
    calendar.ts   날짜·수업일 계산
    rules.ts      필요서류, 일수 계산, 규칙 경고
    stats.ts      현황판 집계
  storage/db.ts   IndexedDB 저장, 백업
  store.tsx       앱 상태
  components/     화면
```

## 미정 / 추후 검토

- 공휴일: 2026·2027년 관공서 공휴일(대체공휴일, 노동절·제헌절 포함)을 기본으로 넣는다 (`src/domain/publicHolidays.ts`). 2028년 이후와 임시공휴일은 교사가 직접 등록하거나 목록을 갱신한다.
- 결석계 제출 기한 규정이 정해지면 기한 경고 추가.

## 나이스 자동 입력 연결

- 지각은 "몇 교시까지 빠졌는지"(조회만 포함), 조퇴는 "몇 교시부터 빠졌는지"를 필수로 입력한다. 체험학습 반일도 같다.
- 「출결 기록 → 나이스 파일」: 기간을 골라 날짜별 한 줄짜리 파일(`attendance_neis_*.json`)을 만든다.
  결과와 교시 없는 지각·조퇴는 자동 입력을 못 하므로 따로 표시한다.
- 나이스 입력은 [YeoBBun/neis-automation-kit](https://github.com/YeoBBun/neis-automation-kit)
  (방배중 안정연 선생님 키트의 포크)의 `app_to_neis.py` 가 다운로드 폴더의 파일을 읽어 키트의 `main.py` 로 넣는다.
  키트의 구글 캘린더 읽기만 바꿔 끼우므로 원본 코드는 그대로이고, 구글 연동이 필요 없다. `/앱출결` 스킬로 실행.
- 나이스는 PC에서만 접속되므로 **PC 웹(학교 PC 크롬)을 기본 사용 환경**으로 본다. 앱 데이터와 다운로드 파일, 키트가 한 PC에 있으면 파일을 옮길 필요가 없다.

## 교내 출결 기준표 반영 (v3)

- 질병결석: 2일 이하 → 결석계만 (보호자 확인은 결석계 담임확인란에 하므로 따로 체크하지 않음), 진료확인서는 선택. 3일 이상이거나 **시험 기간**(설정)에 걸치면 진료확인서·처방전 등 필수.
- 기타: 근거 서류 필수. 학교장이 인정한 부득이한 사유만 해당한다는 안내를 입력 화면에 표시.
- 미인정: 출력물 학생 서명 확인.
- 체험학습: 국내·국외 모두 1회 연속 10일 이내, 연간 20일. 초과분은 미인정결석 대상이라고 경고. 서류는 신청서·보고서 (근거자료(사진·항공권·입장권 등)는 보고서에 첨부하므로 따로 체크하지 않음).
- 경조사: 종류를 고르면 인정 일수(결혼 1, 입양 20, 부모·(외)조부모 사망 5, (외)증조부모 사망 3, 부모의 형제자매 사망 3)를 넘을 때 경고. 일수는 체험학습과 같이 수업일 기준으로 센다 (2026-10 확인).
- 나이스 특기사항 대상(현황판): 질병·미인정 연속 10일 이상(기록이 나뉘어도 이어서 셈), 기타결석, 개근(질병·미인정·기타 기록이 없는 학생).
- 기록 삭제: 확인창 없이 바로 지우고 8초 동안 '되돌리기'.
- 이전 데이터는 불러올 때 서류 필수 여부를 기준표 값으로 맞춘다 (받은 상태는 유지).

- 생리: 결석·지각·조퇴·결과를 통틀어 무조건 달력 월 기준 월 1회 (2026-10 확인).

## 휴대폰 입력 → 학교 PC 자동 입력 (2026-10)

- 학교 업무망에서는 PC용 구글 드라이브 동기화가 막혀 있지만 크롬에서 드라이브 웹 다운로드는 된다.
- 휴대폰: 「나이스 파일 → 드라이브로 보내기」 (공유 창. 안드로이드 크롬이 .json 공유를 막아 같은 내용을 .txt 로 보냄)
- 학교 PC: 크롬에서 드라이브 웹을 열어 파일 다운로드 → 키트의 `app_to_neis.py --auto` 가 예약 시각(평일, 작업 스케줄러)에
  아직 넣지 않은 파일만 넣고 결과를 기록한다. 마감은 선생님이 나이스에서 확인 후.

## 휴대폰 「나이스 반영」 → 학교 PC 자동 입력 (깃허브 연동, 2026-10)

- 설정 → 나이스 자동 연동: 비공개 깃허브 저장소(YeoBBun/school-attendance-sync), 토큰(그 저장소만, Contents 읽기·쓰기), 잠금 비밀번호.
  이 기기의 localStorage 에만 저장하고 백업 파일에는 넣지 않는다.
- 「나이스 반영」: 확인창 → 나이스 입력 파일을 PBKDF2-SHA256(210,000회) + AES-256-GCM 으로 잠가 inbox/ 에 올림.
- 학교 PC 키트(YeoBBun/neis-automation-kit 의 app_sync.py)가 평일 3분마다 확인 → 풀어서 나이스 저장 → results/ 에 결과(건수만).
- 앱은 15초마다 결과를 확인해 「✓ 나이스에 넣었어요」/「확인 필요」를 보여주고, 읽은 결과는 저장소에서 지운다.
- 학교 업무망에서 PC 쪽 구글 드라이브 동기화는 막혀 있어 깃허브를 통로로 썼다 (학교 PC 에서 키트를 깃허브로 받았으므로 접속 가능할 것으로 봄 — 실측 필요).
